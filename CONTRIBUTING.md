# CONTRIBUTING.md (Guia de Contribuição)
Este arquivo explica como alguém pode ajudar no seu projeto, desde reportar bugs até enviar código.

## Por que usar esse arquivo?
* **Escalabilidade:** O _CONTRIBUTING_ economiza seu tempo, pois você não precisará explicar as mesmas regras para cada 
	novo colaborador do projeto.

### Abaixo um exemplo de como pode ser estruturado esse arquivo:

```markdown
# Contribuindo para o Projeto

Ficamos felizes que você queira ajudar! Siga as diretrizes abaixo para manter a organização.

## Como reportar bugs
* Utilize o sistema de **Issues** do repositório.
* Descreva o erro detalhadamente e, se possível, anexe um print.

## Processo de Pull Request (PR)
1. Faça um **Fork** do projeto.
2. Crie uma **Branch** para sua modificação: `git checkout -b feature/minha-melhoria`.
3. Faça o **Commit** das suas alterações com mensagens claras.
4. Envie um **Push** para a sua branch: `git push origin feature/minha-melhoria`.
5. Abra um **Pull Request** detalhando o que foi feito.

## Padrão de Nomenclatura
* Use nomes de arquivos em minúsculas e separados por hífen.
* Siga o padrão de Commits Semânticos (ex: `feat:`, `fix:`, `docs:`).

---
*Ao contribuir, você concorda que seu código será licenciado sob a licença do projeto.*
```
